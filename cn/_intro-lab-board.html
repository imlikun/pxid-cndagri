一句话诊断：现在的开屏是挡在首页前面的另一屏，不是首页的第一帧。三套方案的区别，就是"要不要让它变成第一帧"这件事上给出的三种不同答案。

方案 A起步距离 · 动量交接推荐

开屏里的两个元素，收尾时分别落位成首屏的两个常驻元素：那根 3px 红线缩回成 eyebrow 前实测 36×3 的红短横，字标飞进导航 logo 的实测矩形（82,24 100×27）。黑幕不淡出，而是以这条线为缝向两侧裂开 —— 于是开屏的最后一帧就是首屏的第一帧，中间没有"切换"这个动作。

装置为什么成立：站内已经有这根短横了（.pxid-first-film-eyebrow::before = 36px×3px #e31e29），也有那条 2px 进度轨（.pxid-load-track）。方案 A 没有新造任何视觉元素，只是把已有的进度轨升格为叙事主角，并让它停在已有的落点上。进度改成真资产就绪度；资产先到就满幅"轰油门"（线厚 3→6px 呼吸），绝不假装还在加载。

方案 B车灯显影 · 一次横扫

黑幕不是被撤掉的，是被一道从左侧扫进来的车灯照亮而显影的。进度不挂在长度上，挂在光带的 x 位置上；扫完之后光带收束成一条 3px 红线，再缩回那根短横。

装置为什么成立：首屏那张图本身就是骑行者从左侧冲进画面（hero-mantis-field 视频），"光从左来"和画面里的运动方向同向。相比 A，它多了一层"这是摄影/电影语言"的味道，跟站内那个 pxid-first-film（首片）的命名也接得上。代价：横扫期间文字对比度低，显影不完全时 h1 会糊。

与 A 的可量差异：A 的装置只占 y=489 那一条 3px，其余画面全程纯黑；B 的装置占满 900px 高，画面在 300–1250ms 之间持续处于"半显影"状态。两者对首屏的依赖程度完全不同。

方案 C幽灵里程表 · 排版当主角

主角是一个 150px 的等宽幽灵数字（站内 ghost-number 手法放大一档），真值从 000 跳到 100 后整块转品牌红，然后被首屏从下方"顶"出画面。开屏结束时数字离场，不在首屏留任何痕迹。

装置为什么成立：ODM 这行的买家看的是可交付的数量与节拍，一个跳动的数字比一条进度线更像"工程语言"；等宽数字（tabular-nums，站内 .pxid-load-value 已在用）跳起来不抖。代价：它与首屏没有落位关系，本质上仍是"一屏挡在首页前面"，只是做得更讲究 —— 这是三套里唯一没有解决"两屏感"问题的。

要你拍的三件事

  1. 选哪套，还是 A+B 混。我的建议：A 为主，把 B 的"横扫"借来做 A 的加速段（线头带一道竖向微光扫过首屏宽度），成本很低。C 我不建议 —— 它没有解决"两屏感"，而且站内进度条已经在用一个跳动的百分比数字，再放一个 150px 大数字是自我重复。
  2. 品牌红收敛成哪一套。开屏轨道现在是 #d71920，首屏的 O / F / eyebrow 短横是 #e31e29。选 A 的话必须定一个，因为开屏的终点就是那根短横，颜色不一致会在最后一帧露馅。我倾向统一到 #e31e29（首屏用得更多、更亮），但这会动到 --pxid-red 令牌，影响全站按钮。
  3. 播几次。每次都播（仪式感，回访烦）／ sessionStorage 只播一次 + 点 logo 重播（我推荐）／ 只首次访问播。另外确认一个地板时长：真进度下缓存命中会 300ms 就满，低于 1000ms 人来不及看见开屏，我建议保留这个地板，宁可让线头原地轰油门也不拉长假进度。

不管选哪套，四条实现纪律（已经写进原型）

  1. 几何不写死。内容左边、红线 y、短横宽高、nav logo 矩形全部运行时 getBoundingClientRect() 实测后写进 CSS 变量。站内改一次布局，开屏自动跟着走（实测：桌面 82/489/36×3，移动 390 下自动变 20/552/24×2）。
  2. 进度是真的。分母 = 首屏真用到的资产（hero 图 30% + P6 叠层图 18% + logo 7% + 首屏视频 25% + 字体 20%）；某项挂了或超 1500ms 未就绪就退出统计，从分母里拿掉 —— 否则那个 11MB 的 mp4 能把开屏锁死 6 秒。
  3. 单一状态量驱动，CSS 不参与过渡。踩过的坑：线宽每帧由 JS 内联写入，会把 CSS transition 完全覆盖，交接动画静默失效。改成 p（进度）+ q（交接）两个量逐帧推导后，可重播、可跳帧、可倒放。
  4. 用户一动手就让位。wheel/pointerdown/keydown/touchstart 任一触发立刻跳到揭幕，不逼人看完表演；prefers-reduced-motion 直接给终态。

原型代码已经写到一半（pxid-intro-v1.css / .js，方案 A），本地逐帧验证脚本也在跑。你定完上面三件事我再继续，改哪套都不亏 —— 上面四条纪律是三套共用的。
